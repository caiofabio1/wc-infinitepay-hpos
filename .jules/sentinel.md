## 2024-05-01 - [Webhook Secret Missing Default (Fail Closed)]
**Vulnerability:** The webhook verification logic in `InfinitePay_Webhook::validate_secret` fell back to returning `true` and allowing the payment confirmation to proceed if the `webhook_secret` setting was empty. This would allow an unauthenticated attacker to forge payment confirmations if a merchant did not configure the webhook secret.
**Learning:** In a payment gateway plugin, backwards compatibility or user experience considerations (like allowing an unconfigured plugin to still function if the admin misses a step) must never override security. A missing security mechanism must result in a strict failure ("fail closed"), blocking the payment flow, as accepting unauthenticated webhooks is significantly more dangerous than blocking legitimate webhooks due to misconfiguration.
**Prevention:** Whenever evaluating a conditional branch dealing with authentication, secrets, or integrity checks, explicitly identify what happens if the check is bypassed or not configured, and ensure the default state is `return false` or equivalent rejection.
